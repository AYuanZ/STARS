# Archived profiling data

This directory publishes all 2,852 CSV files from the six model directories in
the existing `Exp/Profiling` archive. The source model names, batch directories,
file names, values, row ordering, headers, and line endings are preserved.
Measurements were copied on 2026-10-26; they were not regenerated by the new
STARS inference checks. The archive contains historical runs and variants.

Original CSV content totals 2,903,891,196 bytes. Lossless storage totals
271,281,321 bytes (258.71 MiB), excluding the small documentation and index
files. Latency tables, KS summaries, and segment indices remain ordinary CSVs;
other exports use deterministic gzip compression. No individual stored data
file exceeds 18 MiB.

The separate latency tables can contain additional batch/SM settings.

processed, joined, and partitioned tables above. Derived tables are included
because they connect the measurements to the released runtime and workload
interfaces. They should not be described as unprocessed measurements.

## Using the latency tables

The main workload-compatible tables are:

- [`bert/all_result/bert.csv`](bert/all_result/bert.csv)
- [`gpt/all_result/gpt.csv`](gpt/all_result/gpt.csv)
- [`resnet/all_result/resnet.csv`](resnet/all_result/resnet.csv)
- [`shufflenet/all_result/shufflenet.csv`](shufflenet/all_result/shufflenet.csv)
- [`vgg/all_result/vgg.csv`](vgg/all_result/vgg.csv)
- [`vit/all_result/vit.csv`](vit/all_result/vit.csv)

From the repository root, with the model dependencies installed:

```bash
PYTHON=python bash scripts/run_model.sh resnet NV \
  --latency-csv data/profiling/resnet/all_result/resnet.csv \
  --batch-mode paper -sm 6 -q 10
```

`batch`, `SM(%)`, and `latency(ms)` are the fields used by the model helper.
`SM(%)` is a legacy header used as an SM-count lookup key. The files retain
repeated measurements and historical settings: BERT has three repeated
batch/SM keys and ViT has 125 repeated keys. The current helper uses the first
matching row, preserving the source behavior. BERT also contains an SM=28
setting; do not assume every archived row represents a physically achievable
allocation on a 26-SM device. No rows were silently removed or averaged.

Filename variants such as `-old`, `-o`, `-128`, or `-32` remain in the archive.
Their names alone do not establish all model, generation-length, clock,
software-version, or checkpoint settings. Do not treat the files as a newly
controlled experiment or assume every variant matches current model defaults.
The profiler exports include recorded device/compute-capability fields, but
the archive lacks a complete environment manifest for every capture.

## Using the KS summaries

The existing directory layout matches the runtime's path-prefix convention:

```bash
export CLIENT_DIR="$PWD/data/profiling/resnet/ks_profiling_result_b"
```

The runtime then appends `${batch}/ks_part/ks_summary_sm_${sm}.csv`. The eight
source columns are positional in the current loader:

```text
ks_id,num_kernels,duration_ns,avg_sm_throughput,avg_dram_throughput,avg_l2_throughput,now_duration_ns,solo_duration_ns
```

`duration_ns` is the sum of kernel durations within a segment, and throughput
columns are duration-weighted means. In this archived export,
`now_duration_ns` repeats the **total** segment duration of the profile in
every row; `solo_duration_ns` is the **cumulative** duration through the current
segment. These legacy names are preserved. All 540 summary files were checked
against that contract. These sums do not necessarily equal wall-clock
inference latency, which also includes gaps, synchronization, and host work.

Supplying the profile prefix alone does not complete STARS workload setup;
MPS, interception, scheduler communication, and workload metadata remain
required. See [the runtime guide](../../docs/RUNNING.md).

## Reading compressed exports

The `.gz` suffix is the only storage-name addition. Decompression restores
the source bytes exactly. For example:

```bash
gzip -dc data/profiling/resnet/ks_profiling_result_b1/ks_new/raw_ncu.csv.gz \
  > /tmp/resnet-b1-raw-ncu.csv
```

Python can read them directly:

```python
import csv
import gzip

path = "data/profiling/resnet/ks_profiling_result_b1/ks_nsys_ncu/output_ncu_nsys_sm_6.csv.gz"
with gzip.open(path, "rt", newline="") as file:
    first_kernel = next(csv.DictReader(file))
print(first_kernel)
```

`raw_ncu.csv` has a units row after its header. `output_all_ncu.csv` also
contains non-CSV application/profiler messages, including original diagnostic
language and paths. Monitor files can contain short status records such as
`timestamp,ID` in addition to regular GPU records. Preserve or explicitly
filter these records when parsing; a generic rectangular-CSV reader is not
appropriate for every raw export.

## Provenance and verification

- [`manifest.csv`](manifest.csv) maps each published file to its original
  source-relative path, category, compression, byte sizes, and SHA-256 hashes
  of both stored and original bytes.
- [`source_inventory.csv`](source_inventory.csv) lists all files found in the
  source profiling tree, including files outside the published scope.
- [`summary.json`](summary.json) records file counts and bytes by model/category.
- [`validation.json`](validation.json) records verified file counts, latency
  coverage, repeated keys, and the checked KS duration contract.

Recheck downloaded data from the repository root:

```bash
python3 scripts/verify_profiling_data.py
```

The importer is also included for reproducibility. It requires the existing
source archive and refuses to overwrite published data files:

```bash
python3 scripts/import_profiling_data.py \
  --source /path/to/Exp/Profiling --destination /tmp/stars-profiling-copy
```

All six models' CSV exports are published. The source inventory also lists
1,620 binary reports/databases/plots for those models (`.ncu-rep`, `.nsys-rep`,
`.sqlite`, and `.png`); their payloads are not committed to this source
repository. The original source tree additionally contains 742 Inception
files, which are outside the six-model workload scope. A listed inventory
entry is not a download link to an unpublished file. Complete experiment
results outside `Exp/Profiling` are not part of this profiling-data snapshot.
